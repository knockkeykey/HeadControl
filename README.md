# 头势控制

AirPods Pro 2 的原生 macOS 菜单栏工具：**头势 → 快捷键或指定应用**。SwiftUI + AppKit + Core Motion，macOS 15.3+、Apple Silicon。

## 使用

1. 打开 `build/HeadControl.app`，在“状态”连接耳机。收到耳机数据后，若尚未校准，会自动弹出提醒；点击“校准”后正对屏幕保持静止一秒，即可自动完成。选择“稍后”不会在本次连接中反复提醒，仍可从页面手动校准；重新连接或已有校准失效时会再次提醒。
2. 在“头势”页分别开启需要的头势，再选择点按快捷键、切换到应用、不操作或暂停控制。录入时区分左右修饰键，也可直接选右 Option、Return、Esc、空格。
3. 在“头势”页逐项练习，每个头势完成三次往返；按需手动采用建议，再使用“联合测试”检查实际识别结果。所有测试均不执行动作，不发键也不切换应用。
4. 点击“头势”页顶部或“状态”页的“启动头势控制”，切到你要操作的应用。

未启动控制时，只要耳机已连接并校准，停留在“状态”或“头势”页都能识别已开启的头势：“状态”页即时更新“最近一次”和事件记录；“头势”页仪表显示绿勾、卡片闪绿。两页均播放该头势的提醒音，提示“已达标 · 未启动控制”；不会发送快捷键、切换应用或执行暂停动作。成功反馈约四秒后消失，仍按设置的冷却时间和收回要求允许下一次识别。切到“通用”页或关闭、最小化、隐藏设置窗口后停止这类预览反馈；声音遵循通用提示音开关和单项静音设置。未启动提示提供直接启动按钮，准备未完成时指向“状态”页。

启动始终默认暂停。修改开关、绑定或识别参数会清空未完成的动作，控制保持当前状态；测试模式中可继续调节。耳机断连、数据中断、左右耳来源改变、重新校准、锁屏、屏幕休眠或离开当前会话也会暂停控制；恢复后需重新校准并手动开启。修改某个头势的识别参数或开关会使该头势的测试结果与建议失效；只修改按键、目标应用或提醒音不影响识别测试结果。

| 头势（按卡片顺序） | 默认启用 | 默认快捷键 |
|---|---|---|
| 左歪头 | 开启 | 右 Option 单击 |
| 右歪头 | 开启 | 不操作 |
| 完整点头 | 开启 | Return 单击 |
| 向左转头 | 关闭 | 不操作 |
| 向右转头 | 关闭 | 不操作 |
| 完整摇头 | 关闭 | 不操作 |

每个头势都有独立开关，与“执行”设置分开保存。关闭后完全不参与识别，不播放提醒音，不发送按键，也不占用全局冷却时间；按键、参数和提醒音仍保留，重新开启可继续使用。“不操作”表示保留识别与提醒音，但不发键；不需要识别的头势应直接关闭。逐项练习只包含已开启项，每个目标收集三次从回正区出发并回位的完整动作。三次幅度相近时，以中间值的约 70% 建议幅度和速度；幅度差异较大时提示重试。采集不依赖当前触发门槛，门槛过高也能练习；测试通过标记仅在三次动作都被当前参数识别时出现。采用建议仍需手动点击，不会自动开启速度条件。

联合测试让所有已开启头势同时识别，并按头势计数。可切换“做指令动作”和“观察日常动作”：前者检查动作串扰，后者观察看屏幕、说话、低头时的识别是否为误触。切换阶段重新计数，日常观察不标记测试通过；修改识别设置会清空联合记录。所有测试都不会发键或切换应用，结束后保持暂停。

所有绑定全局生效。快捷键动作中的右 Option 是否切换语音、Return 是否发送或换行，取决于当前应用和输入法设置。快捷键动作只点按一次，不判断录音、文字是否完成或消息是否发送；不区分微信、GPT、Codex，也不读取输入框。可随时改键或禁用任一头势。

每次触发只点按一次，不持续按住、不执行多步骤宏。所有按键（含单独的 Option、Shift、Control、Command）都通过 HID 事件发送，输入法（如微信输入法的右 Option 语音）才能收到，并保留左右键身份。点头和摇头需完整动作；不需要先回正，任何姿势下都能开始做头势；持续歪头不会连续发键，触发后在该方向收回到阈值的 70% 以内并经过冷却才能再次触发。修改设置不会暂停头势控制，新设置从下一个动作开始生效。与实际键盘修饰键冲突时跳过，按下／松开配对执行；若采集到动作后、发键前切换前台应用，本次操作跳过。

## 切换到应用

在头势卡片的“执行”菜单选择“切换到应用”，搜索已安装应用，或点“选择其他应用…”指定其他位置的 `.app`。应用列表扫描 `/Applications`、`~/Applications`、`/System/Applications` 和系统附加应用目录，不扫描整个磁盘；同名应用显示路径。卡片显示目标图标和名称，点击即可更换。

目标已运行时切到前台，未运行则启动；已经在前台时保持，不额外发键。窗口、桌面与全屏空间遵循应用和 macOS 的原生切换行为。应用位置变化时尝试按 Bundle ID 找回；卸载、找不到或启动失败时提示原因，保留绑定，不自动弹窗。设置、菜单栏与悬浮条显示相同的目标和执行结果。

选择器打开期间临时屏蔽头势执行，关闭后恢复原控制状态；取消不修改绑定。切换动作种类时分别记住之前的快捷键和应用，重新录制快捷键也保留应用选择。控制未启动、逐项练习、联合测试和走动暂停均不会切换应用。总开关仍沿用现有运动与健身、辅助功能／事件发送授权要求。

## 调节与反馈

提示音在识别完成时立即播放，早于快捷键发送；测试、暂停动作及未绑定动作也保留识别反馈。每个头势可单独选音或静音，“通用”的提示音开关控制实际头势反馈。播放器预先准备所选声音，跟随当前普通音频输出；AirPods 输出设备或采样率变化时重建，播放启动失败时重建重试一次，仍失败则记录到事件列表。试听和实际触发共用播放路径，不需要麦克风权限。

头势页取消灵敏度档位，各参数独立手动调整：拖动圆弧圆点设置动作幅度；歪头／转头设置持续时长，点头／摇头设置完成时限和回位范围；各头势均可设置冷却时间。速度条件有独立开关，全部默认关闭，关闭后慢动作也可触发，仍须满足幅度和时间条件；开启后用“慢 ↔ 快”滑块设置速度门槛，点头和摇头要求往返两个方向都达标。关闭速度条件会保留滑块数值，重新开启时继续使用。各参数旁的问号可点开查看含义及调节影响。测试时记录实际幅度和速度，“采用建议”只在手动点击时应用，不会开启速度条件。走路或跑步时自动暂停识别、停下后自动恢复，可在“通用”关闭。悬浮条不抢输入焦点，明确区分已发键、跳过执行、测试未发键和未设置动作；未完成头势会提示幅度、保持时间、回位或速度原因。临时结果和提示约四秒后消失，最近一次及带时间的事件记录仍保留，相邻重复记录合并并显示次数；悬浮条提供暂停按钮。提示音、悬浮条、走动暂停与程序坞图标可在“通用”关闭。

## 暂停与电源管理

实时活动声明只在已连接的控制、测试或稳定校准期间持有；走动暂停、手动暂停、断连及系统挂起时释放。活动允许系统正常空闲睡眠，不再申请阻止空闲睡眠。暂停且设置窗口／菜单均关闭时，不做相对姿态计算、识别或界面刷新；保留连接和样本到达检测，不宣称关闭耳机传感器。步行活动更新仅在控制或测试中开启。

锁屏、屏幕休眠、系统睡眠及会话离开会清空待执行动作、停止采集并撤销校准；对应恢复事件全部到齐后重启连接监听，控制仍保持暂停。校准须连续静止一秒，移动或样本中断会重新计时，十秒未稳定可重试或取消。

## 权限与隐私

头势控制只需要运动与健身、辅助功能／事件发送权限，不需要麦克风。不连接服务器、不读取或保存任何输入文字。

配置保存到 `~/Library/Application Support/com.keyknock.HeadControl/configuration.json`。版本 6 新增应用切换动作，保存应用名称、位置和可用的 Bundle ID；兼容读取版本 1–5。应用被移动或卸载不会使其他配置恢复默认。版本 5 新增六个独立头势开关；版本 1–4 迁移时默认只开启左右歪头和完整点头，保留原有绑定、参数和提醒音。速度条件开关与头势开关互相独立。版本 4 起保存全局绑定、独立的头势参数、每个头势的速度开关和反馈偏好，不再保存灵敏度档位。版本 3 迁移时保留所有参数，速度条件默认关闭，按需手动开启；更早版本保留原参数并从旧档位补足速度数值。版本 1 首次载入时先备份原文件，保留头势参数、提示音和悬浮条设置，绑定改为默认的全局按键；旧的应用和语音状态配置不再参与控制。无效／较新版本的配置保留原件，暂停保存并提示备份后重置。

## 使用的耳机数据

- `CMHeadphoneMotionManager` / `CMDeviceMotion`：校准后的转头、点头、歪头角度，以及对应轴的角速度（用于速度门槛）。头势识别接收每个样本，界面只显示小球、圆弧和简单状态，不展示原始数值。
- `CMHeadphoneActivityManager`（macOS 15+）：只用来判断是否在走路或跑步，以便自动暂停；不显示、不保存活动记录。

不接入私有蓝牙协议或未公开的传感器接口。

苹果文档：[耳机运动](https://developer.apple.com/documentation/coremotion/cmheadphonemotionmanager)、[运动样本](https://developer.apple.com/documentation/coremotion/cmdevicemotion)、[耳机活动](https://developer.apple.com/documentation/coremotion/cmheadphoneactivitymanager)、[音频输入](https://developer.apple.com/documentation/avfaudio/avaudioengine/inputnode)。

最终应用标识为 `com.keyknock.HeadControl`；Debug 为独立的 `com.keyknock.HeadControl.Debug`。两者在系统设置里都显示为 “头势控制”，权限应授予最终 `build/HeadControl.app`。应用以 Developer ID 签名，重新构建后权限保持有效。

## 构建与测试

```sh
cd /Users/keyknock/Downloads/cut/HeadControl
./scripts/test.sh
# 验证提示音先于发键、启动失败恢复，并实际播放系统提醒音（无需麦克风或发键权限）
./scripts/test-sound-feedback.sh
# 检查应用切换动作的路由、临时屏蔽、失效及反馈，不实际切换应用
./scripts/test-application-controller.sh
# 会打开独立测试窗口，验证真实冷启动、后台切换和隐藏／最小化恢复；不发送按键
./scripts/test-application-switching.sh
# 使用合成运动渲染实际界面及明暗应用选择器，不播放声音、不发键、不修改用户配置
./scripts/test-interface.sh
# 生成隔离的交互夹具，用于检查 状态 → 头势 → 通用 → 头势 的导航及滚动
./scripts/test-interface.sh /tmp/headcontrol-navigation --interactive
# 需本机已有 Debug 版事件发送权限；会打开专用接收窗口，约 12 秒
./scripts/test-key-delivery.sh
./scripts/build.sh
open build/HeadControl.app
```

Xcode 打开 `HeadControl.xcodeproj`，选择 HeadControl scheme。工程无第三方依赖，脚本仅为当前命令指定 Xcode，不更改全局 xcode-select。Release 2.1.0 (4)，arm64，Developer ID 签名（团队 MR285FSGSG）与 hardened runtime，未公证。

- `Core`：配置迁移、头势识别、全局路由、按键序列规划及自动化测试。
- `HeadControl/Platform`：耳机、按键发送、配置存储、悬浮条。
- `HeadControl/Views`：原生设置、快捷键录入、姿态与动作测试。
- `VALIDATION.md`：已完成的技术检查与真机验证边界。
